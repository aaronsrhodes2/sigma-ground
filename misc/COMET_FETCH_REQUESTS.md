# Comet truth data: the exact requests (for the Captain's approval before any fetch)

Source: JPL Horizons API (public domain, no account). One request per (comet, window); each returns a header with the orbital solution used (including the non-gravitational parameters A1, A2, A3 and the epoch) and the barycentric ICRF state vector at six epochs: the window start and +1..+5 yr, at EXACTLY the fixture's snapshot epochs (TDB JD).
Expected size: 2 to 6 KB per response, 60 requests, about 250 KB total, saved to D:/datasets/jpl/horizons_comets/ (a new empty directory) one file per request. Requests are sent one at a time, 0.5 s apart.
Plan: send the FIRST request alone (1P, j2010), check that the response parses (CAP choosing the apparition, units, frame), then send the rest only if it does.
Why `DES=<n>;CAP`: Horizons holds a separate orbital solution per apparition for most periodic comets; CAP picks the apparition closest to the epoch, so the start state and the later 'truth' come from the same solution.
