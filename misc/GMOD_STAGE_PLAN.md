# GMod Stage Plan — Mentat experiments as watchable, operable Garry's Mod scenarios

**Status:** proposed 2026-10-09, not started.
**Owner:** Captain. **Author:** Claude (session 36).

## 1. Goal and success criterion

**Success (Captain's words):** every prior sigma-ground experiment can be run
inside Garry's Mod as a *separate, Lua-generated scenario* that the Captain can
watch and operate from inside the environment.

Translated into checkable terms:

1. One Lua file per experiment, generated by Python from the existing bundle
   data, loadable by name from the GMod console or a spawn-menu tab.
2. Playback is sigma-ground-authoritative: bodies follow the recorded
   trajectory (position, orientation, temperature) at the bundle's own rate.
3. "Operate" means the Captain can pause, scrub, change rate, walk around,
   and at any moment grab a body with the physgun or hit `release`, at which
   point that body is handed to Havok with its current velocity and the scene
   carries on under GMod's own physics.
4. Every scenario in the inventory below is either ported, scaled-and-ported,
   or explicitly marked "not ported, and why".

## 2. Non-goals

- Replacing Materia, `dynamics/` or Mentat. They stay the authoritative solver.
- Real-time sigma-ground physics inside GMod at 66 Hz. GLua only speaks HTTP;
  live coupling is limited to slow phenomena (thermal) and to generating new
  scenarios from a sentence (Phase 5).
- Rendering the cosmological or subatomic end of sigma-ground at true scale.
  Source is a float32, room-scale world. Those scenes get a stage scale.
- Fluids. GWater2 exists if we ever want water on screen; we do not reimplement it.

## 3. Why GMod, and what happens to Radiance and Deckard

**Mentat is done.** It is web-accessible, impressive, and remains the physics
agent. This plan only changes where the pictures come from.

**Radiance: freeze after extracting the exporter.** The trajectory contract in
`sigma_ground/radiance/trajectory.py` (frames of `{pos, quat, temperature_k?}`)
and the thermal recorder are exactly what the GMod player needs. The SDF
ray-marcher, the CSG leaf-count work and the leaf-stress benchmarks become
moot the day the first scenario plays in GMod. The web viewer stays as a
fallback, with no further rendering work planned.

**Deckard: retire the research-then-fit-primitives path.** The catalog cites
Claude's own priors as sources (see `catalog/coffee_cup.md`, "typical stoneware
mug (approx.), conf 0.60"). That loop never had an outside anchor for form, so
it never got past primitives in space. What survives: the density and material
tables, the mass/CoM/inertia integrator, and the voxel path's idea of
ingesting a human-authored mesh. Shapes now come from GMod's prop library or
from runtime primitives sized by the bundle's own scene leaves.

**GMod now, s&box later.** GMod has a 20-year-old Lua API that does not break,
a double-precision VPhysics since April 2026, 64-bit builds since September
2026, HTTP from Lua, and thousands of props. s&box has a far better renderer
and C#, but its own docs describe the API as preview-stage with frequent
breaking changes. Phase 6 is the decision gate; the scenario format is engine
neutral on purpose so a port costs only the player, not the exporter.

## 4. Architecture

```
sigma-ground (Python, authoritative)              Garry's Mod (Lua, the stage)
┌──────────────────────────────┐                  ┌──────────────────────────────┐
│ radiance/web/data/*.json     │  export_gmod.py  │ addon/lua/mentat/scenarios/  │
│ (existing bundles)           │ ───────────────► │   <name>.lua  (one per expt) │
│                              │  (Phase 0-4)     │                              │
│ Materia verbs / thermal      │                  │ addon/lua/mentat/player.lua  │
│ Mentat front door (web)      │ ◄──── HTTP ────► │   replay · release · HUD     │
│                              │  (Phase 5 only)  │ addon/lua/mentat/live.lua    │
└──────────────────────────────┘                  └──────────────────────────────┘
```

**Two modes per scenario.**

- **REPLAY.** Bodies are `MOVETYPE_NONE`; the player sets position and angles
  every tick from the interpolated trajectory (the Lua twin of `poses_at`).
  Temperature drives the body colour. Havok is not consulted. No velocity
  clamp, no map-speed limit applies, because nothing is simulated.
- **RELEASE.** On `mentat_release`, or when the physgun grabs a body, that body
  becomes `MOVETYPE_VPHYSICS` with mass from the bundle and velocity from the
  trajectory derivative. From then on Havok owns it. The player keeps logging
  its Havok position next to the bundle's, so the gap is a free
  "test against reality" record (Platinum rule: compare against something real
  or at least independent).

**Transport.** Phases 0 to 4 need no network at all: Python writes Lua files.
Phase 5 adds HTTP from the GMod server to the Mentat web endpoint. GMod blocks
HTTP to localhost unless the game is launched with `-allowlocalhttp`; note it
in the addon README.

## 5. Units, axes, and engine limits that shape the design

| Topic | Source engine | sigma-ground | Handling |
|---|---|---|---|
| Length | Hammer unit, 1 HU = 0.75 in = 0.01905 m, so 1 m = 52.49 HU | metres | `SCALE_HU_PER_M = 52.4934 * stage_scale`, per scenario |
| Up axis | Z up | **per bundle**: 53 viewer bundles Y-up, 32 theater bundles Z-up (found in Phase 0) | exporter reads `physics_env.gravity_dir`, else `camera.up`, and cross-checks the motion; Y-up maps Source X=x, Y=-z, Z=y |
| Orientation | Angle (pitch, yaw, roll) degrees | quaternion `[x,y,z,w]` | `quat_to_angle()` in Lua, ~15 lines |
| Gravity | `sv_gravity` 600 HU/s² = 11.43 m/s² | 9.81 | set 515 HU/s² when a scenario is released |
| Mass | `PhysObj:SetMass` clamps at 50,000 kg | anything | fine for room scale; astronomical bodies are replay only |
| Map extent | about ±16,384 HU, ~620 m across | anything | `stage_scale` and `time_rate` per scenario |
| Velocity | clamped in VPhysics (default not verified; the wiki page 404'd) | anything | irrelevant in REPLAY; RELEASE only for room-scale scenes |
| Shapes | compiled MDL props, or runtime convex hulls (`PhysicsInitMultiConvex`, `PhysicsInitSphere`, `PhysicsInitBox`) | CSG leaves of Sphere/Box/Cylinder plus Deckard constructs | leaf → primitive; label → prop via a shape table; fallback convex hull |
| Render mesh cap | 65,535 vertices per IMesh | n/a | chunk if ever needed; primitives never hit it |

## 8. Generated scenario format

Each `<name>.lua` returns a plain table, engine-neutral on purpose:

```lua
return {
  name = "fall_skillet", source = "radiance/web/data/fall_skillet.json",
  stage_scale = 1.0, time_rate = 1.0, gravity_m_s2 = 9.81, atmosphere = "IRT",
  bodies = {
    { label = "cast iron skillet", mass_kg = 2.1, material = "cast_iron",
      shape = { type = "Cylinder", r = 0.13, h = 0.05 },   -- from the scene leaf
      prop = "models/props_c17/metalPot001a.mdl" },        -- optional, from shape_table.json
  },
  frames = {   -- t_sim, then per body: x,y,z, qx,qy,qz,qw, [T]
    { 0.000, { {0,0,2.00, 0,0,0,1} } },
    { 0.050, { {0,0,1.99, 0,0,0,1} } },
    ...
  },
  audio = { { t = 0.31, file = "bell_strike_iron_150mm.wav" } },  -- class B only
}
```

Positions are in metres in the file; the player converts. Frames are
down-sampled by the exporter if a bundle exceeds ~5,000 poses so a file stays
well under 1 MB (the 60 s clock is 1,202 frames × 7 bodies, fine).

## 9. Console surface (what "operate" means in practice)

| Command | Effect |
|---|---|
| `mentat_list` | print scenario names and classes |
| `mentat_load <name>` | clear stage, spawn bodies at frame 0, paused |
| `mentat_play` / `mentat_pause` | run / hold sim time |
| `mentat_rate <x>` | playback rate multiplier |
| `mentat_scrub <t_sim>` | jump to a sim time |
| `mentat_release [label]` | hand one body, or all, to Havok with current velocity |
| `mentat_reset` | back to frame 0, all bodies kinematic again |
| `mentat_say "<sentence>"` | Phase 5: ask Mentat to simulate, load the result |

Physgun grab on a replay body implies `mentat_release` for that body (hook
`PhysgunPickup`). HUD overlay (clientside, networked): scenario name, class,
t_sim, rate, stage scale, per-body temperature when present, and a
"RELEASED" tag per body.

## 11. Validation (Platinum: test against reality, dry-run first)

- The exporter has a round-trip test: scenario Lua → parsed by a tiny Lua
  reader in Python (or `lupa`) → poses equal the bundle's `poses_at` within
  float tolerance.
- RELEASE logs Havok positions beside bundle positions into
  `garrysmod/data/mentat/<name>_release.json`. A Python script reports the
  divergence per body. Expect agreement for ballistic falls and disagreement
  for anything with drag (Havok has none), which is itself the useful result.
- Phase 3 thermal: the colour ramp samples the same blackbody table the web
  viewer uses, so a screenshot pair is the check.
- Nothing in GMod is treated as ground truth. Where Havok and sigma-ground
  disagree, both numbers go in the session log and neither is "fixed".

## 12. Risks and open questions

- **Physgun versus kinematic bodies.** Setting position every tick fights the
  physgun. The hook-based auto-release is the mitigation; needs testing in
  Phase 1.
- **64-bit branch.** PCGamingWiki reports unstable collisions on it. Use the
  main branch for RELEASE comparisons until verified.
- **Prop masses and sizes.** HL2 props are modelled at their own scale and
  masses are arbitrary. The player always overrides mass from the bundle and
  may need `SetModelScale`; where scale mismatch is ugly, the primitive
  fallback is more honest than a wrong-sized prop.
- **Localhost HTTP** needs `-allowlocalhttp`. Phase 5 only.
- **Mentat web endpoint shape.** Phase 5 assumes a JSON route that accepts a
  sentence and returns a trajectory bundle. Confirm what the deployed Mentat
  exposes before Phase 5; the exporter's bundle → scenario code is reused on
  the Lua side either way.
- **Steam library path** for the junction: confirm before running mklink.
- **What is "operate" beyond physgun and console?** A spawn-menu tab with a
  scenario list and transport buttons is a cheap Phase 2 extra if the console
  feels thin.

## 14. Phase 0 findings (measured 2026-10-09, corrections to the sections above)

**What was built.** Exporter `sigma_ground/radiance/export_gmod.py`; addon under
`stage/gmod/addon/` (loader, shared scenario cache, `mentat_body` entity, server replay and
release, HUD, autotest); independent grader `stage/gmod/verify_autotest.py`; 35 offline tests
(`test_gmod_stage.py`, `test_gmod_verify.py`). README: `stage/gmod/README.md`.

**Corrections to this plan**

1. **Up axis is per bundle**, not Z everywhere (section 5 fixed). 53 viewer bundles are Y-up,
   32 theater bundles are Z-up, and two bundles lie: `falling_aluminum_ball` and
   `falling_lead_ball` declare Z-up in `camera.up` but fall along Y. The exporter warns on
   any such mismatch instead of guessing.
2. **`fall_skillet` never lands.** The bundle ends at t = 0.76 s with the pivot 0.24 m up, so the
   cylinder base is 0.196 m above the floor and still falling at about 7.4 m/s. The Phase 0
   done criterion was changed accordingly. Replay ends in mid-air; release lets Havok finish.
3. **The "skillet" is a generic vessel.** Its geometry is a 15 cm x 12 cm cylinder shell with a
   zero-thickness water film, the same fallback the Deckard cup spec produces. It is the
   clearest single example of the Deckard shape problem described in section 3.
4. **Pivot semantics.** The viewer places a leaf at `pos + R*(local - pivot)`; `pos` is the
   pivot's world position. The entity origin in GMod is therefore the pivot (the centre of
   mass in the bundles checked), and shape centres are exported relative to it.
5. **Nine mechanism bundles append their final frame twice** with an identical pose
   (`clock`, `escapement_clock`, `gear_mesh`, `gear_train`, `motor_spin`, `windmill_*`). The
   exporter collapses exact duplicates and refuses two different poses at one timestamp.

**Consequences for the phases.** Phase 1's done criterion (the plate-off-the-table scene)
needs Torus and Clipped shapes, or a stand-in decision for the doughnut. Phase 2 needs Cone,
Ellipsoid, Rotated and Gear support, plus a Voxel path (marching cubes in Python, then convex
decomposition for the hull, or a prop-library stand-in). The cheapest high-value order is
Rotated and Gear (mechanisms), then Cone and Ellipsoid, then Torus and Clipped, then Voxel.

**A gap this surfaced.** sigma-ground has deformation physics at the material level
(Hertz contact, yield and plasticity, restitution, fracture toughness, Paris fatigue, creep in
`field/interface/`) but nothing that changes a body's shape: the trajectory frame contract
carries `pos`, `quat` and `temperature_k` only, `dynamics/` is rigid-body, SPH and a hydro
continuum, and `impact.py` returns scalars. A scenario can therefore never show a dent or a
break. GMod has no real deformation either (Deformator-style mesh swaps only), so this is a
sigma-ground capability to design, with a per-vertex or per-cell displacement channel
alongside the existing temperature channel, not something the stage will supply.
